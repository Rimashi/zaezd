# Правила внесения изменений

Эти правила нужны для ЛР1 и должны соблюдаться для изменений проекта.

## Обычное изменение

1. Создать задачу (Issue) в GitHub/GitLab.
2. Создать отдельную ветку от `main`.
3. Сделать несколько осмысленных коммитов.
4. Выполнить локальную проверку `make check`.
5. Отправить ветку в удалённый репозиторий.
6. Создать Pull Request / Merge Request.
7. Просмотреть изменения и только после этого слить в `main`.

Пример:

```bash
git switch main
git pull
git switch -c feature/auth

# изменения
git add .
git commit -m "add login api"

# ещё изменения
git add .
git commit -m "connect login form to backend"

make check
git push -u origin feature/auth
```

## Что запрещено

- хранить `.env` в Git;
- хранить реальные пароли и токены в коде;
- коммитить `.venv`, `venv`, `__pycache__`;
- работать над новой функцией прямо в `main`;
- удалять проверки только ради того, чтобы изменение прошло.

## Как показать конфликт слияния

Самый простой учебный вариант:

1. В ветке `conflict-a` изменить одну строку в `README.md` и сделать коммит.
2. Вернуться в `main`, изменить ту же строку иначе и сделать коммит.
3. Попытаться слить `conflict-a` в `main`.
4. Git покажет конфликт.
5. Открыть файл, убрать маркеры `<<<<<<<`, `=======`, `>>>>>>>`, оставить правильный вариант.
6. Выполнить `git add README.md` и `git commit`.

## Тег первой версии

После того как ЛР1 готова и изменения находятся в `main`:

```bash
git switch main
git pull
git tag -a v0.1.0 -m "Laboratory work 1"
git push origin v0.1.0
```
