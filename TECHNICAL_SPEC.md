# Техническое задание — информационная система управления соревнованиями по скачкам

## 1. Назначение

Система предназначена для хранения и обработки данных о соревнованиях по скачкам: лошадях, жокеях, командах, соревнованиях, заездах, составе заездов и результатах.

## 2. Пользователи

### Администратор

В первой версии является основной учётной записью и может выполнять все операции системы: вести справочники, создавать соревнования и заезды, формировать состав и вносить результаты.

### Организатор

Роль предусмотрена моделью данных. Может работать со спортивной частью системы, но не управляет учётными записями.

### Зритель

Зритель работает без учётной записи. Ему доступен только просмотр соревнований, заездов, участников и результатов. Изменение данных без аутентификации запрещено.

## 3. Основные сценарии

1. Зритель открывает сайт без входа и просматривает соревнования, заезды, участников и результаты.
2. Администратор входит по логину и паролю.
3. Администратор добавляет лошадей и жокеев.
4. Из одной лошади и одного жокея создаётся команда.
5. Создаётся соревнование.
6. Внутри соревнования создаются заезды.
7. Команды заявляются в конкретный заезд и получают стартовые номера.
8. Соревнование и заезд переводятся в состояние проведения.
9. После завершения заезда фиксируются результаты.
10. После завершения всех заездов соревнование можно завершить.

## 4. Основные сущности

- `User` — учётная запись;
- `Horse` — лошадь;
- `Jockey` — жокей;
- `Team` — переиспользуемая пара лошадь + жокей;
- `Competition` — соревнование;
- `Race` — заезд внутри соревнования;
- `RaceEntry` — участие команды в заезде;
- `Result` — результат одного участия.

Полная схема находится в `schema.dbml`.

## 5. Бизнес-правила

1. Одинаковая пара лошади и жокея не создаётся дважды.
2. В одном заезде одна лошадь не может участвовать через несколько команд.
3. В одном заезде один жокей не может участвовать через несколько команд.
4. Стартовый номер уникален внутри заезда.
5. В заезд можно заявить только лошадь и жокея со статусом `active`.
6. Состав заезда меняется только до его начала.
7. Для снятого участника указывается причина снятия.
8. Результат создаётся только для существующего участия в завершённом заезде.
9. Для одного участия существует не более одного результата.
10. Для статуса `finished` обязательны место и время.
11. Одно место не может принадлежать двум финишировавшим участникам одного заезда.
12. Соревнование нельзя завершить, пока все его заезды не завершены или не отменены.
13. После завершения соревнования его результаты не изменяются.

## 6. Обработка ошибок

Приложение должно обрабатывать:

- обращение к несуществующей записи;
- неверные данные формы;
- нарушение уникальности;
- нарушение бизнес-правил;
- запрос без аутентификации;
- запрещённую операцию для роли;
- недоступность БД при healthcheck.

Некорректный HTTP-запрос не должен аварийно завершать приложение.

## 7. Хранение данных

Используется PostgreSQL. Связи задаются внешними ключами, уникальные ограничения и простые числовые ограничения контролируются базой данных.

Пароли в открытом виде не хранятся. В таблице `users` находится только `password_hash`.

Строка подключения, пароль первого администратора и секрет cookie передаются через переменные окружения и не должны попадать в Git.
